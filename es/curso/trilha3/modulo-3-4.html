🧩 Skills: habilidades empaquetadas

Tu Jarvis ya tiene manos (herramientas) y un alma (identidad). Falta darle recetas: pasos a paso que no tienes que repetir cada vez. Eso es una skill — un archivo de texto que empaqueta «cómo hacer tal cosa». En este módulo entenderás qué es una skill, por qué conviene empaquetar, cómo ahorran memoria, en qué se diferencian de una herramienta, cómo funcionan en más de un programa y cómo mejoran por sí solas.

📒 Qué es una skill

Imagina una receta de cocina guardada en una carpeta. No es el pastel, ni el horno, ni la harina: es el paso a paso que indica, en el orden correcto, qué hacer con todo esto. Una skill (habilidad) es exactamente eso para tu Jarvis: un archivo de texto que empaqueta un procedimiento repetido. Cuando dices «escribe una publicación para LinkedIn», la skill correspondiente ya conoce la secuencia: investigar el tema, crear un gráfico, escribir el texto, revisarlo y publicarlo, sin que tengas que explicar cada paso otra vez.

¿Eres nuevo aquí? Una skill y una «receta reutilizable» guardada en un archivo de texto llamado SKILL.md. O .md y es solo la extensión de Markdown: texto simple con títulos y listas que cualquiera puede leer y editar en el bloc de notas. No es un programa, no necesitas instalar nada: son instrucciones escritas que Jarvis sigue.

🧩 Anatomía de una skill

Toda skill tiene dos partes: un encabezado corto (la «etiqueta» de la receta, con el nombre y cuándo usarla) y el cuerpo (el paso a paso real). El encabezado siempre está a la vista; el cuerpo solo se lee cuando se invoca la receta.

  • •Nombre — cómo se llama la skill (p. ej., post-linkedin).
  • •Descripción — una frase que diga cuando activar (y eso es lo que hace que Jarvis decida usarla).
  • •Pasos — la receta en sí: haz esto, luego aquello, con este criterio.

La gran revelación es que una skill es conocimiento que se convierte en capacidad. Enseñas el procedimiento una vez, por escrito, y queda disponible para siempre —en cualquier conversación, sin que tengas que recordar los detalles. Y como es solo texto, puedes leerlo, editarlo y versionarlo como cualquier documento.

Conceptos clave

Skill

Una receta: paso a paso empaquetado en un archivo de texto.

SKILL.md

El archivo Markdown que guarda el nombre, la descripción y los pasos.

Markdown (.md)

Texto simple, legible para las personas, sin programar nada.

Conocimiento → capacidad

Escribes el procedimiento una vez; se convierte en una habilidad permanente.

2

📦 Por qué empaquetar

Sin skills, te conviertes en un disco rayado: cada vez que pides lo mismo, tienes que volver a explicar los 5 pasos. "Investiga el tema, pero usa solo fuentes de 2025; después, haz un gráfico sencillo; el texto debe tener como máximo 3 párrafos; revisa el tono; y solo entonces publícalo". Repetir todo eso en cada solicitud te cansa, y el resultado sale diferente cada vez, porque la explicación nunca es idéntica.

✗ Sin skill (explicarlo cada vez)

  • ✗Vuelves a escribir los mismos pasos con cada solicitud.
  • ✗El resultado varía: a veces olvida la revisión, a veces el límite de párrafos.
  • ✗El conocimiento solo vive en tu cabeza — nadie más lo reutiliza.
  • ✗Mejorar el proceso significa recordar cambiar la explicación la próxima vez.

✓ Con skill (basta una frase)

  • ✓Dices "haz una publicación para LinkedIn" y los pasos se ejecutan solos.
  • ✓El resultado es coherente: la misma receta, siempre.
  • ✓La receta está en un archivo; puedes compartirlo con el equipo.
  • ✓¿Mejoró? Edita el archivo una vez y sirve para siempre.

📊 Tres beneficios concretos de empaquetar

  • •Consistencia: la misma calidad cada vez, porque el paso a paso no cambia.
  • •Velocidad: una frase en lugar de un párrafo de instrucciones.
  • •Repositorio: cada skill que escribes queda en el estante: se convierte en una biblioteca de capacidades.

Conceptos clave

Empaquetar

Guardar un procedimiento repetido en un archivo, en lugar de en tu memoria.

Consistencia

La misma receta produce el mismo patrón de resultados.

Repositorio de skills

Tu biblioteca de habilidades crece y se reutiliza.

Editar una vez

La mejora queda en el archivo y sirve para todos los usos futuros.

3

🔎 Carga progresiva

Aquí está el truco que hace que las skills sean baratas. Recuerda que el LLM tiene una memoria de trabajo limitada — la ventana de contexto (lo vimos en la Ruta 1). Si volcaras el texto completo de 50 skills en esa memoria, se llenaría antes incluso de empezar. La solución es el carga progresiva (en inglés, progressive disclosure): Jarvis solo ve, todo el tiempo, el etiqueta de cada skill: nombre y descripción, algo como ~100 tokens. El cuerpo pesado (la receta completa) solo se lee cuando esa skill se activa realmente.

¿Eres nuevo aquí? Frontmatter y es el encabezado en la parte superior del archivo (nombre + descripción), entre dos líneas de tres guiones ---. Token y es el fragmento de texto que el modelo cuenta como «memoria usada». Progressive disclosure = "revelar poco a poco": muestra solo la etiqueta hasta que necesitas el contenido. Es como el índice de un libro: lees los títulos de los capítulos y solo abres el que te interesa.

A la izquierda, la biblioteca guarda decenas de skills, pero solo expone la etiqueta de cada una (barato). Cuando activas una, el cuerpo completo de la receta entra en la memoria de trabajo: solo esa, solo en ese momento. Así es como tener muchas skills no satura el contexto.

Conceptos clave

Progressive disclosure

Revelar solo la etiqueta hasta que se active la skill.

Frontmatter

El encabezado ligero (nombre + descripción) siempre a la vista.

~100 tokens

El costo mínimo de mantener una skill disponible.

Ahorro de contexto

Decenas de skills sin saturar la memoria de trabajo.

4

🔧 Skills vs. herramientas

Cuidado con confundir los dos, porque sus nombres suelen aparecer juntos. En el módulo anterior (3-3) viste herramientas: las «manos» de Jarvis: buscar en la web, leer un archivo, enviar un correo electrónico. Una herramienta es una acción atómica: hace una algo y devuelve el resultado. Una skill y es otra capa: es un procedimiento que decide cuáles qué herramientas llamar, en qué orden y qué hacer con cada resultado. La herramienta es el verbo; la skill es la receta que usa varios verbos.

🍳 La metáfora de la cocina

En una cocina, las herramientas son el cuchillo, el horno y la batidora; cada uno realiza una acción. La skill y es la receta del pastel: "bate los huevos (batidora), corta la fruta (cuchillo), hornea 40 min (horno)". La receta orquesta las herramientas con criterio: sabe el orden, las cantidades y cuándo algo salió mal.

Sin herramientas, la receta no tiene con qué trabajar. Sin la receta, tienes herramientas sueltas y ningún pastel.

🔨 Herramienta = acción atómica

  • •«buscar en la web», «leer archivo», «enviar correo electrónico».
  • •Hace una algo y devuelve un resultado.
  • •No decide nada por sí sola: alguien tiene que invocarla.
  • •Suele llegar por MCP (el «USB» de las herramientas, del módulo 3-3).

🧩 Skill = procedimiento + criterio

  • •«escribir una publicación», «hacer un resumen del día», «clasificar la bandeja de entrada».
  • •Orquesta varias herramientas, en el orden correcto.
  • •Aplica un criterio: "si no encuentras una fuente, avisa antes de publicar".
  • •Es solo texto (SKILL.md): no instala nada, solo describe cómo hacerlo.

En resumen: herramienta responde «qué puedo hacer» (una acción). Skill responde «cómo hago tal cosa bien hecha" (un procedimiento con criterio, que usa varias acciones). Una skill casi siempre usa herramientas, pero no todas se convierten en skills.

Conceptos clave

Acción atómica

Una herramienta hace una sola cosa y devuelve el resultado.

Orquestación

La skill encadena herramientas en el orden adecuado y con criterio.

Juicio

La skill decide qué hacer cuando algo sale de lo esperado.

Capas que se suman

Herramienta = verbo; skill = receta que usa varios verbos.

5

🔁 Portabilidad (polyskill)

Porque una skill es solo un archivo de texto que sigue un formato acordado (la Especificación de Agent Skills), no queda atada a un programa. La misma receta puede ejecutarse en Claude Code y en el Codex (dos asistentes de IA diferentes): basta con una herramienta llamada polyskill que toma una única fuente y genera la versión adecuada para cada uno. Escribes la skill una vez; sirve en más de un lugar.

¿Eres nuevo aquí? Especificación de Agent Skills y es solo un «formato acordado»: un estándar para escribir el archivo de skill, para que distintos programas sepan leerlo. Polyskill y es el traductor: a partir de una única fuente, emite (genera) la versión para cada programa. Entre entornos de ejecución = "se ejecuta en más de un entorno de ejecución". Portabilidad = la propiedad de llevar lo mismo de un lugar a otro sin reescribirlo.

⚠️ Honestidad: lo que «múltiples modelos» NO quiere decir aquí

Cuando se dice que las skills funcionan con «varios modelos», eso es portabilidad (la misma receta funciona en Claude Code y Codex), y no un consejo de varios cerebros que opinan juntos, ni una recomendación sobre qué modelo elegir. Portabilidad = un archivo, varios destinos. Nada de votación mágica entre modelos. (Volvemos a este mito en el módulo 3-6, sobre Cerebros.)

🧪 Ejemplo COPY-RUN · tu primer SKILL.md

Objetivo: crear una skill mínima y portable: un SKILL.md con encabezado (nombre + descripción) y los pasos de la receta. Después generamos la versión para otro programa con polyskill.

1) Crea la carpeta y pega el contenido de abajo en el archivo SKILL.md (cambia las partes <...>):

mkdir -p ~/.jarvis/skills/<nome-da-skill>
cat > ~/.jarvis/skills/<nome-da-skill>/SKILL.md <<'EOF'
---
name: <resumo-do-dia>
description: Use quando eu pedir um resumo do meu dia. Le a agenda
  e os e-mails nao lidos e devolve 3 bullets curtos.
---

# Resumo do dia

Passos:
1. Buscar os compromissos de hoje na agenda.
2. Listar os e-mails nao lidos das ultimas <24h>.
3. Resumir em <3> bullets curtos, do mais urgente ao menos.
4. Se nada for urgente, dizer "dia tranquilo" e parar.
EOF

2) (Opcional) Genera la versión para otro programa a partir de esta única fuente:

polyskill build ~/.jarvis/skills/<nome-da-skill> --target codex

Cómo verificar: ejecuta cat ~/.jarvis/skills/<nome-da-skill>/SKILL.md y comprueba que el archivo se abra con ---, tiene name: e description:, y luego los pasos numerados. En tu Jarvis, pide «dame el resumen del día»: si sigue los 4 pasos en orden, reconoció la skill. Si ejecutaste el paso 2, comprueba que apareció una versión en la carpeta de salida de polyskill para el destino codex.

Observación didáctica: nombres de comandos (polyskill) y las rutas son ilustrativas del concepto; lo importante es la estructura del archivo (encabezado entre --- + pasos). La spec es el formato; el programa solo lee.

Conceptos clave

Especificación de Agent Skills

El formato combinado que permite que varios programas lean la skill.

Polyskill

El traductor: a partir de una única fuente, genera la versión de cada destino.

Entre entornos de ejecución

La misma skill funciona en Claude Code y en Codex.

Portabilidad ≠ consejo

"Varios modelos" aquí = un archivo, varios destinos.

6

🌱 Las skills se autocorrigen

La parte más bonita: una skill no es una piedra, sino algo vivo que mejora con el uso. Cada vez que se ejecuta la receta, tú (o el propio Jarvis) notas qué se podría mejorar: «faltó verificar la fuente», «el tono quedó demasiado formal», «este paso era innecesario». Como la skill es solo texto, basta editar el archivo y la próxima ejecución ya sale mejor. La receta aprende de su propia práctica.

1

Funciona

La skill ejecuta la tarea de verdad: genera la publicación, hace el resumen.

2

Observa

Notas un inconveniente: faltó un paso, sobró otro, el resultado necesitaba un ajuste.

3

Edita el SKILL.md

Ajustas el texto de la receta: una línea más, un criterio más claro.

4

Mejora a partir de ahí

La corrección se aplica a todas las próximas ejecuciones — sin que tengas que recordarlas.

📚 La biblioteca de skills y su colección de capacidades

Cada skill que escribes y perfeccionas queda guardada. Con el tiempo, no tienes «un asistente»: tienes un colección de habilidades afiladas que solo crece. Un Jarvis con 20 skills buenas vale mucho más que un modelo sin procesar, porque incluye procedimientos probados en tu realidad.

Y como todo es texto legible, este acervo «sobrevive a la moda»: la tecnología cambia, pero tus recetas siguen siendo válidas.

📊 Por qué esto es tan poderoso

  • •Mejora compuesta: los pequeños ajustes se acumulan: la skill de hoy es mejor que la de ayer.
  • •Memoria de proceso: la lección aprendida queda en el archivo, no en tu cabeza.
  • •Transferible: una skill madura se puede compartir con otras personas ya pulida.

Autoevaluación (opcional): ¿qué frase describe mejor qué es una skill?

Conceptos clave

Autocorrección

Cada ejecución revela un ajuste; editar el archivo mejora el futuro.

Mejora compuesta

Los pequeños refinamientos se acumulan con el tiempo.

Repositorio de capacidades

Tu biblioteca de Skills bien afinadas es lo que hace que Jarvis sea tuyo.

Sobrevive al hype

Es solo texto: sigue siendo válido incluso cuando cambia la tecnología.
